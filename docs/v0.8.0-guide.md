## 1. Virtual DOM (VDOM)

TW v0.9.30 introduces a lightweight, TW-native Virtual DOM — no React dependency, no fibers, no reconciliation overhead. ~3KB gzipped runtime (vs traditional frameworks' ~45KB).

### How it works

- **Build-time:** Compiler detects reactive features (state, events, bind, show, tw-for)
- **Client-side:** VDOM runtime diffs old vs new tree, applies minimal DOM patches
- **Batched updates:** Multiple state changes = single DOM mutation pass via `requestAnimationFrame`
- **Keyed children:** O(n) diffing with key-based reordering

### Enabling VDOM

VDOM is auto-detected. If your page uses `state {}`, `on:click`, `bind:value`, `show:`, `tw-for`, or `tw-text`, the VDOM runtime is automatically injected.

```tw
page {
    title "Counter"
    render interactive
}

state {
    count 0
}

body {
    button { on:click "count++" } "Increment"
    p { tw-text "count" } ""
}
```

You can also force VDOM with `render interactive`:

```tw
page {
    title "Dashboard"
    render interactive
}
```

### VDOM Directives

| Directive | Example | Effect |
|-----------|---------|--------|
| `state {}` | `state { count 0 }` | Reactive state variables |
| `bind:value` | `input { bind:value "name" }` | Two-way input binding |
| `on:click` | `button { on:click "count++" }` | Event handler |
| `show:` | `div { show:visible "count > 0" }` | Conditional display |
| `tw-text` | `p { tw-text "count" }` | Dynamic text content |
| `tw-if` | `div { tw-if "show" }` | Conditional rendering |
| `tw-else` | `div { tw-else }` | Else branch |
| `tw-for` | `ul { tw-for "items" }` | List rendering |
| `tw-key` | `li { tw-key "item.id" }` | Keyed list items |
| `tw-ref` | `input { tw-ref "myInput" }` | DOM reference |
| `tw-class` | `div { tw-class '{"active":"isActive"}' }` | Conditional classes |

### VDOM API (JavaScript)

The VDOM runtime exposes a public API on `window.__tw`:

```javascript
__tw.set("count", 5);           // Set state value
__tw.get("count");              // Get state value
__tw.watch("count", fn);        // Watch a state value
__tw.refs.myInput;              // Access DOM ref
__tw.fetch("/api/data");        // Fetch helper
__tw.action("createPost", data); // Call server action
__tw.h("div", {class: "card"}, [__tw.text("Hello")]); // Create VNode
```

### Why TW VDOM is better than React

| Feature | TW VDOM | React |
|---------|---------|-------|
| Runtime size | ~3KB gzipped | ~45KB gzipped |
| Diffing | O(n) single pass | Fiber reconciliation |
| Hydration | None — server HTML IS initial state | Complex hydration |
| Batched updates | Built-in via rAF | Requires hooks |
| Dependencies | Zero | React + ReactDOM |

## 2. Lib System Overhaul

v0.9.30 brings Next.js-style module imports to TW.

### Import Syntax

```tw
import { getApps, getApp } from "@/lib/data"
import formatPrice from "@/lib/utils"
import * as api from "@/lib/api"

page {
    title "Apps"
    render static
}

let apps = getApps()
let featured = getApp("calculator")

body {
    each apps as app {
        div { class "card"
            h1 "{app.name}"
            p "Price: {formatPrice(app.price)}"
        }
    }
}
```

### Module Resolution

| Prefix | Resolves to |
|--------|-------------|
| `@/lib/data` | `<project_root>/lib/data.twm` |
| `./utils` | `<current_dir>/utils.twm` |
| `../shared` | `<parent_dir>/shared.twm` |

### .twm File Syntax

```javascript
// Server-side function (default — runs at build time)
export async function getApps() {
    const data = await fetch("https://api.example.com/apps");
    return data.json();
}

// Client-side function (ships to browser)
export client function formatPrice(n) {
    return "₹" + n.toFixed(2);
}

// With type annotations (stripped before execution)
export function getApp(slug: string): Promise<App> {
    const apps = getApps();
    return apps.find(a => a.slug === slug);
}
```

### Async/Await Support

```javascript
export async function fetchUsers() {
    const res = await fetch("https://api.example.com/users");
    const data = await res.json();
    return data.filter(u => u.active);
}
```

### Type Annotations

Type annotations are supported and stripped before execution:

```javascript
export function calculate(a: number, b: number): number {
    return a + b;
}

export function getUser(id: string): Promise<User> {
    return users.find(u => u.id === id);
}
```

### Client-Side Functions

Functions marked with `export client` are shipped to the browser:

```javascript
export client function formatPrice(n) {
    return "₹" + n.toFixed(2);
}
```

These are automatically extracted and injected into the page's `<script>` tag.

## 3. Server Actions

Server Actions let you call server-side functions from client-side events — no API route needed.

### Defining Actions

```tw
action createPost {
    method POST
    handler "createPost"
    require_auth true
}

action deletePost {
    method DELETE
    handler "deletePost"
    require_auth true
}
```

### Calling Actions from Client

```tw
body {
    button { on:click "__twAction('createPost', { title: 'Hello' })" } "Create Post"
}
```

### Action Flow

1. Client calls `__twAction("actionName", arg1, arg2)`
2. POST request to `/__tw/actions/actionName`
3. Server validates CSRF + auth
4. Server executes handler
5. Response can include `__twSetState` to update client state

## 5. ISR

Incremental Static Regeneration — pages regenerate in the background after a specified time.

```tw
page {
    title "Products"
    render static
    revalidate 60
}
```

This regenerates the page every 60 seconds in the background. The first request after 60s triggers regeneration; subsequent requests get the fresh version.

## 6. Suspense & Streaming

Progressive page loading with Suspense boundaries.

### Client-side Suspense

```javascript
__twSuspense("content-id", "loader-id");
```

When streaming content arrives, the loader is hidden and content is shown.

## 7. Error Boundaries

`error.tw` catches runtime errors and displays a fallback UI.

```
[home]/
└── error.tw       ← catches errors for the segment
```

The error boundary JS is automatically injected into pages that need it.

## 8. Zero-JS Preservation

Static pages remain Zero-JS — no VDOM runtime, no state, no event handlers.

```tw
page {
    title "About"
    render static
}

body {
    h1 "About Us"
    p "We build amazing things."
}
```

This page ships with **0 bytes of JavaScript**.

### Rules

- `render static` → Zero-JS guaranteed
- No `state {}` block → Zero-JS
- No `on:*` events → Zero-JS
- `render interactive` → VDOM runtime injected
- Auto-detect: if `state` or events present → VDOM auto-injected
