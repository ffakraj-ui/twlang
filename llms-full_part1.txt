================================================================================
0. WHAT TW IS (AND IS NOT)
================================================================================

TW ("TW Framework", package name `tw-framework`, PyPI) is a custom language +
framework in one package. It is NOT React, NOT Vue, NOT Svelte, and NOT
TypeScript, although it borrows ideas from each. It CAN use React alongside
its own VDOM via the React compatibility layer (v0.8.1+).

- Language: `.tw` files (markup + page logic) and `.tss` files (styles) compile
  to plain HTML, CSS, and JS. TW has its own lexer, parser, and compiler
  pipeline written in Python.
- Framework: file-based App Router routing, `.twm` API routes, middleware,
  dev server, NPM package manager, React compatibility, esbuild bundling,
  client-side bundler, security module.
- Package manager: `pip install tw-framework` (Python). NPM packages via
  `tw install` command (auto-detects npm/pnpm/yarn/bun).

2. PROJECT STRUCTURE (App Router)
================================================================================

```
my-project/
  tw.config                  # Required. Simple key-value config.
  package.json               # Optional. For npm dependencies (tw install).
  middleware.tw              # Optional. Global request middleware.
  vercel.json                # Optional. Vercel deployment override.
  netlify.toml               # Optional. Netlify deployment override.
  [home]/                    # App Router root (literal brackets)
    layout.tw                # Root layout
    page.tw                  # Home page (route: /)
    about/
      page.tw                # Route: /about
    blog/
      page.tw                # Route: /blog
      [slug]/
        page.tw              # Dynamic route: /blog/:slug
      (dashboard)/           # Route group (doesn't appear in URL)
        layout.tw
        stats/
          page.tw            # Route: /stats
    api/
      route.twm              # API route: /api
      health/
        route.twm            # API route: /api/health
    lib/                     # Lib modules (.twm files for shared logic)
      data.twm
      utils.twm
      react-component.twm   # React component module
    not-found.tw             # 404 page
    error.tw                 # Error boundary
```

3. PAGE SYNTAX
================================================================================

Every `.tw` page file MUST start with a `page { }` block.

Valid keys inside `page { }`:
  - title (string, required) — page title
  - render (string) — static | server | edge | interactive | dynamic
  - layout (string) — layout name (filename without .tw)
  - revalidate (number) — ISR seconds
  - responsive (boolean) — enable responsive meta tags

Example:
```tw
page {
    title "About"
    render static
}

body {
    h1 "About Us"
    p "We build amazing things."
}
```

Render modes:
  - static (default) — Zero-JS HTML
  - interactive — VDOM runtime + React integration
  - server — Server-side rendering
  - edge — Edge rendering
  - dynamic — With generateStaticParams

4. BODY SYNTAX
================================================================================

Tag patterns:
  - Tag with text: `h1 "Welcome"`
  - Tag with attributes: `div { class "container" }`
  - Tag with both: `a "Click" { href "/page" class "btn" }`
  - Nested children: `div { class "box" h1 "Title" p "Text" }`
  - Text pseudo-attribute: `p { class "desc" text "Content" }`

Attribute syntax: space-separated key-value pairs inside { }. No equals signs.
Reactive directives use colons: on:click, bind:value, show:visible, tw-text.

CRITICAL: Use `text "..."` for text content inside { } blocks, NOT bare strings.
  WRONG: button { on:click "count++" "+" }
  CORRECT: button { on:click "count++" text "+" }

  - npm: install --save-dev / uninstall / install

6. REACT COMPATIBILITY (v0.8.1+)
================================================================================

Module: tw_framework/react_compat.py

ReactCompat class:
  - is_react_installed() — checks node_modules/react/package.json
  - get_react_version() — reads version from installed React
  - get_bootstrap_js() — returns REACT_BOOTSTRAP_JS (defines __tw.react API)
  - get_react_loader_script(use_cdn=True) — returns script tags:
    - Installed + CDN: uses installed version (react@17/18/19, NOT hardcoded)
    - Installed + no CDN: points to /js/react-bundle.js
    - Not installed + CDN: latest CDN fallback
    - Not installed + no CDN: empty string
  - detect_react_usage(source) — checks for React imports, useState, etc.

Build pipeline integration (v0.8.1 fix — was dead code before):
  - _inject_react_integration() in compiler.py
  - Called in render_html() both branches (layout + default)
  - Also called in framework.py App Router modular pipeline
  - Detects React in .tw source, .twm modules, and render interactive mode
  - Injects bootstrap JS + loader script before </body>
  - Config: react_cdn (default true) — set false to bundle from node_modules

React page example:
```tw
import { Counter } from "@/lib/react-component"

page {
    title "React Demo"
    render interactive
}

body {
    div { id "react-root" }
    script { on:load "__tw.react.mount('Counter', 'react-root')" }
}
```

7. ESBUILD INTEGRATION & CLIENT BUNDLER (v0.8.1+)
================================================================================

Module: tw_framework/esbuild_integration.py
  - detect_esbuild() — finds esbuild binary (npx esbuild or local)
  - get_esbuild_version() — caches version globally
  - bundle_with_esbuild(entry, outfile, options) — invokes esbuild CLI

Module: tw_framework/client_bundler.py
  - ClientBundler class:
    - bundle_package(pkg_name) — tries esbuild first, falls back to IIFE
    - bundle_imports(source) — finds imports, bundles each package
    - render_chunk_script_tags() — uses _topological_sort() (Kahn's algorithm)
    - _topological_sort() — dependency ordering with cycle detection
    - Transitive deps: iterates _cache to find and write all deps to disk + import map
    - Fallback warning: "esbuild is not installed — using fallback IIFE bundler"

esbuild bundling:
  - process.env.NODE_ENV = "production"
  - Output format: IIFE
  - Target: browser
  - CLI syntax: --flag=value (not --flag value)

8. ROUTE PATH GENERATION (v0.8.40 FIX)
================================================================================

Three functions generate route paths — all now consistent:

1. route_path_from_page_info() in compiler.py
   - Used for: __TW_DATA__ JSON, HTML metadata comments
   - Fix: checks url_path first, then falls back to rel_dir + name
   - App Router: skips name if it's already the last segment of rel_dir

2. route_from_static_page() in framework.py
   - Used for: sitemap.xml, RSS feed
   - Fix: same url_path-first logic + duplicate detection

3. route_from_dynamic_page() in framework.py
   - Used for: sitemap.xml dynamic routes
   - Fix: url_path with segment substitution for dynamic params

Before fix: /about/about, /contact/contact, /counter/counter
After fix: /about, /contact, /counter

Pretty URLs (pretty_urls: true in tw.config):
  - /about → dist/about/index.html (NOT dist/about/about/index.html)
  - App Router: rel_dir already contains route name, name NOT appended again

9. LIB SYSTEM & .twm MODULES
================================================================================

Import syntax in .tw pages:
  import { getApps, getApp } from "@/lib/data"
  import formatPrice from "@/lib/utils"

.twm module files:
  - Server-side functions: export async function, export function
  - Client-side functions: export client function (shipped to browser)
  - Type annotations: stripped before execution
  - NPM imports: import dayjs from "dayjs" (resolved via createRequire)

Lib executor (tw_framework/lib_executor.py):
  - Bridge script uses createRequire for npm package resolution
  - Env helpers: globalThis.env, globalThis.secrets, globalThis.firebase, globalThis.helpers
  - No Module._resolveFilename override (removed for stability)

twm_parser.py (tw_framework/twm_parser.py):
  - Parses .twm files — imports, exports, async/await, type annotations
  - Returns dict with {exports, client_exports, source}
  - _convert_es_import_to_cjs() — converts ESM imports to CJS require

10. API ROUTES (.twm)
================================================================================

File naming: MUST be route.twm
  [home]/api/route.twm → /api
  [home]/api/health/route.twm → /api/health

Handler functions:
  fn get(request) { return { json: { ok: true } }; }
  fn post(request) { return { status: 201, json: { created: true } }; }
  fn handler(request) { ... } // catches all methods
  async fn get(request) { const data = await http.get(url); return { json: data }; }

Request object:
  request.method, request.path, request.query, request.body,
  request.headers, request.cookies, request.env, request.project_root

Response formats:
  - String → 200 text/plain
  - Plain object → 200 application/json (auto)
  - Explicit: { status, headers, json, text, html, body, content_type, cookies }
  - Tuple: [{ ok: true }, 200, { "X-Test": "1" }]

Built-in helpers:
  - http.get/post/put/patch/delete(url, options?) — async HTTP client
  - env.KEY / env.get("KEY") / env.require("KEY")
  - secrets.KEY / secrets.get("KEY") / secrets.require("KEY")
  - pkg.require("package-name") — load npm package from node_modules
  - firebase.app() / firebase.firestore() / firebase.auth()

13. VIRTUAL DOM & REACTIVITY (v0.8.0+)
================================================================================

VDOM: auto-detected (~3KB, no React dependency). Injected when page uses state, events, or bindings.

State:
  state { count 0 name "hello" items [] }

Bindings:
  - bind:value "name" — two-way binding
  - on:click "count++" — event handler
  - show:visible "count > 0" — conditional display
  - tw-text "count" — text binding
  - tw-html "htmlContent" — HTML binding
  - tw-ref "myInput" — DOM ref (window.__tw.refs.myInput)
  - tw-class '{"active": "isActive"}' — conditional classes
  - tw-for "items" — list rendering

Built-in: __twToggleTheme (toggles data-theme="dark" on <html>)
Client fetch: window.__twFetch(url, options)
