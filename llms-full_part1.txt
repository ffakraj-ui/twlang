================================================================================
0. WHAT TW IS (AND IS NOT)
================================================================================

TW ("TW Framework", package name `tw-framework`, PyPI) is a custom language +
framework in one package. It is NOT React, NOT Vue, NOT Svelte, and NOT
TypeScript, although it borrows ideas from each. It CAN use React alongside
its own VDOM via the React compatibility layer.

- Language: `.tw` files (markup + page logic) and `.tss` files (styles) compile
  to plain HTML, CSS, and JS. TW has its own lexer, parser, and compiler
  pipeline written in Python.
- Framework: file-based App Router routing, `.twm` API routes, middleware,
  dev server, NPM package manager, React compatibility, esbuild bundling.
- Package: `pip install tw-framework` (Python). NPM packages via `tw install`.
- Core dependencies: ZERO — pure Python stdlib. Optional extras available.
- Project root marker: `tw.config` file.
- Source folder: `[home]/` (literal brackets — App Router root).

================================================================================
1. SYNTAX — .tw FILES
================================================================================

TW uses block-based syntax with curly braces. NOT JSX. NOT HTML angle brackets.

### 1.1 Page Block
```tw
page {
    title "My Page"
    render static
}
```

### 1.2 Render Modes
- `render static` — SSG, build-time HTML (default)
- `render server` — SSR, per-request server render
- `render edge` — edge runtime via V8 sandbox
- `render interactive` — TW native VDOM (~3KB), reactive on demand
- `render dynamic` — auto-detect static vs server
- `render csr` — full React CSR, client-side hydration

### 1.3 Page Directives
- title — string
- render — static | server | edge | interactive | dynamic | csr
- revalidate — number (seconds) for ISR
- cache_by — cookie:name, header:name, query, or custom
- cache_size — integer (default 512)
- generateStaticParams — string path to JSON data file
- redirect — string URL
- rewrite — string URL

### 1.4 Elements
```tw
body {
    div { class "container"
        h1 "Hello World"
        p { class "subtitle", text "Welcome to TW" }
        a { href "/about", text "About Us" }
    }
}
```

### 1.5 Components
```tw
component Button {
    props {
        href: string = ""
        label: string = "Click"
        variant: string = "primary"
    }
    style {
        .btn { padding: 0.5rem 1rem; border-radius: 0.375rem; }
    }
    body {
        a { class: "btn btn-{{variant}}", href: "{{href}}", text: "{{label}}" }
    }
}
```

### 1.6 Conditionals
```tw
if condition {
    p "Visible when true"
}
else {
    p "Visible when false"
}
```

### 1.7 Loops
```tw
each items as item {
    li "{{item.name}}"
}
```

### 1.8 Let Bindings
```tw
let greeting = "Hello"
let count = 42
```

### 1.9 Reactive State
```tw
state {
    count 0
    name "World"
}
```

### 1.10 Event Handlers
```tw
Button { label "Increment", on:click "increment" }
```

### 1.11 Server Actions
```tw
actions {
    fn increment(state) {
        state.count = state.count + 1
    }
}
```

### 1.12 Head Block
```tw
head {
    meta { charset "utf-8" }
    meta { name "viewport", content "width=device-width, initial-scale=1" }
    seo {
        description "Page description"
    }
}
```

### 1.13 Layouts
```tw
page {
    title "My Site"
    render static
}

load "@./style.tss"

head {
    meta { charset "utf-8" }
    meta { name "viewport", content "width=device-width, initial-scale=1" }
}

body {
    Navbar {}
    main { class "main-content"
        children
    }
    Footer {}
}
```

2. TSS — TW STYLE SYSTEM (.tss files)
================================================================================

```tss
:root {
    --bg: #ffffff;
    --text: #1a1a1a;
    --primary: #3b82f6;
}

body {
    background: var(--bg);
    color: var(--text);
    font-family: system-ui, sans-serif;
}

@media (prefers-color-scheme: dark) {
    :root {
        --bg: #0f172a;
        --text: #e2e8f0;
    }
}
```

Components have scoped CSS via `style { }` blocks — styles do not leak.
CSS Modules built in.

3. TWM — API ROUTES (.twm files)
================================================================================

### 3.1 Basic API Route
```twm
runtime = "nodejs"

fn get(request) {
    return {
        status: 200,
        body: { message: "Hello from API" }
    }
}

fn post(request) {
    const data = request.body
    return {
        status: 201,
        body: { created: true }
    }
}
```

### 3.2 Runtime Directives
- runtime = "nodejs" (default) — persistent Node.js worker
- runtime = "edge" — V8 sandbox via py_mini_racer
- runtime = "python" — Python in-process
- runtime = "wasm" — wasmtime sandbox
- runtime = "edge-py" — legacy Python edge fallback

### 3.3 Common API Layer (tw.*)
- tw.storage.read/write/delete/exists(path)
- tw.http.fetch/get/post/put/delete(url, ...)
- tw.crypto.hash/hmac/random/uuid/encrypt/decrypt(...)
- tw.cache.get/set/delete/has/clear(key, ...)
- tw.env.get/all/has(name)
- tw.runtime.name/version/capabilities/supports()

4. MIDDLEWARE (middleware.tw)
================================================================================

### 4.1 Rule-based middleware
```tw
use {
    match "/dashboard/**"
    header "X-Content-Type-Options" "nosniff"
}

rule "api-rate-limit" {
    match "/api/**"
    rate_limit { requests 100, window 60 }
}
```

### 4.2 Function-based middleware
```tw
fn before(ctx) {
    if (ctx.path.startsWith("/admin") && !ctx.session) {
        return { redirect: "/login" }
    }
}

fn after(ctx) {
    ctx.response.headers["X-Response-Time"] = ctx.duration + "ms"
}
```

### 4.3 Middleware capabilities
- Path matching: prefixes, contains, extensions, regex
- deny_traversal, deny_null_bytes, single_segment_max
- Headers, methods, auth (cookie, JWT)
- Rate limiting (token bucket)
- User agent, origin (CORS)
- Redirect, rewrite, custom response

5. APP ROUTER
================================================================================

### Route segment types:
- Static: about/ → /about
- Dynamic: [slug]/ → /:slug
- Catch-all: [...slug]/ → /*
- Optional catch-all: [[...slug]]/ → /*?
- Route group: (group)/ — no URL segment

### Special files:
- page.tw, layout.tw, not-found.tw, error.tw, loading.tw, route.tw

================================================================================
6. SECURITY
================================================================================

- CSP nonce generation, CSP header builder with directive dedup
- HTML/URL/attribute sanitization with double-escape protection
- CSRF token generation and validation
- Security headers: X-Frame-Options, X-Content-Type-Options
- Request body size limit (10MB default)
- Env var filtering for Edge runtime
- V8 execution timeout (30s)
- Authenticated encryption (scrypt + HMAC-SHA256)
- Null byte removal

7. PRODUCTION SERVER
================================================================================

- tw serve — 0.0.0.0:8000
- SSR for render server/edge pages
- Static file serving with ETag, Cache-Control, brotli/gzip
- API route execution (Node.js, Edge V8, Python, WASM)
- Middleware chain

9. MULTI-RUNTIME
================================================================================

| Runtime | Key | Engine | Capabilities |
|---------|-----|--------|-------------|
| Node.js | nodejs/node | Persistent Node.js worker | fs:Y, net:Y, subprocess:Y |
| Edge V8 | edge/edge-v8 | V8 isolate (py_mini_racer) | fs:N, net:Y, crypto:Y |
| Python | python | Python in-process | fs:Y, net:Y, subprocess:Y |
| WASM | wasm | wasmtime sandbox | fs:N, net:N, crypto:Y |
| Edge (legacy) | edge-py | Python in-process | fs:N, net:Y, crypto:Y |

Thread-safe registration via register_runtimes() with double-check lock.
